# AI 拍照助手 · 最小原型（浏览器版）

零依赖前端原型，用来验证"拍前一句提示"这条链路。**不需要安装任何东西、不需要下载模型**。

## 三个页面

| 页面 | 用途 |
|---|---|
| **`live.html`（默认）** | **实拍版**：接真实摄像头，实时检测地平线/亮度/反光/竖直线，识别建筑或风景并给出**目标构图引导**，能真的拍照 |
| `showcase.html` | **演示版**：合成场景 + 一键 30 秒脚本，不需要摄像头，适合答辩放 |
| `index.html` | **调试版**：虚拟倾斜、阈值滑杆、事件日志导出，用来调参 |

## 目标构图引导（建筑 / 风景）

实拍版会自动识别场景，给出一个**可以达成的目标**——不是"你错了"，而是"把主体对准这里"：

| 场景 | 判定依据 | 目标呈现 | 达成条件 |
|---|---|---|---|
| **建筑** | 竖直线多 + 有天空 | 虚线**目标框**（楼体范围 + 楼顶留白线） | 楼顶留白 8–15%、竖线偏离 < 2° |
| **风景** | 竖直线少 + 天空 + 地平线 | 三分线处的**目标虚线** + 上下箭头 | 地平线落在 1/3 或 2/3（±5%） |

引导文案示例：

- 建筑："后退半步，把楼顶收进来" / "走近一点，让建筑占满画面" / "手机往左转一点，让柱子竖直"
- 风景："抬一点手机，把地平线抬上去" / "压一点手机，把地平线降下来"

**优先级**：有基础问题（歪/暗/反光）时先说问题，没有问题时才给构图目标——保证一屏只有一条指令。

按 `G` 键可开关目标引导。

## 演示版怎么用（`showcase.html`）

打开后点「开始演示」，会自动播放 9 段脚本（约 30 秒）：

| 时间 | 场景 | 你会看到 |
|---|---|---|
| 0s | 水平、明亮 | 提示条收起，只显示快门 |
| 3s | 相机歪 14° | 提示 "Level the horizon" + 旋转箭头 + 当前角度 |
| 9s | 摆正 | 提示消失，变成 "Hold still — you can shoot" |
| 12s | 光线太暗 | "Move to the light" |
| 18s | 镜头反光 | "Angle away from the glare" + 高光区域框 |
| 24s | 往另一边歪 | 反向箭头提示 |
| 30s | 结束 | 回到就绪 |

侧栏还有单步按钮（拿歪/变暗/反光）、**「关闭助手（对照组 A）」**——同一个场景关掉助手后什么都不提示，这就是你们 A/B/C 条件的直观演示。

> 说明：画面是**合成场景**，但检测、规则、提示全部是真实代码在跑（`detect.js` 真的在做边缘检测和直方图统计），不是写死的动画。

## 运行

**推荐：双击 `run.py` 或 `run.bat`** —— 会自动起服务器并打开浏览器。

命令行方式（等价）：

```powershell
cd web-prototype
python run.py                 # 自动选端口 + 开浏览器
python run.py --no-open       # 只起服务
python run.py --port 9000     # 指定起始端口
```

启动后窗口里会打印地址，形如 `http://127.0.0.1:8765/index.html`。
**用完再关这个窗口**——窗口一关服务器就停了，浏览器就打不开了。

> 常见问题：双击没反应 → 说明 `.py` 没关联到 Python，改用 `run.bat`；浏览器没自动弹出 → 手动复制窗口里打印的地址；端口被占用 → 程序会自动换成下一个端口，看窗口里打印的实际端口。

## 怎么用

| 操作 | 说明 |
|---|---|
| **开始（摄像头）** | 授权后进入实时模式，处理笔记本/手机摄像头 |
| **演示模式**（或按 `D`） | 无摄像头也能测：合成一个可调倾斜角的场景 |
| `←` / `→` | 调整演示场景的倾斜角（-15° ~ 15°） |
| **虚拟倾斜**（滑杆 / `[` `]` / `Z` 归零） | 笔记本摄像头转不动时用：把画面旋转 N° 后再检测，等效于"相机拿歪了" |
| **助手：开/关**（或空格） | 对应设计里的"任意状态可静音" |
| **模拟快门**（或 `S`） | 记录一次 capture 事件，并重置提示冷却 |
| 倾斜阈值滑杆 | 实时改规则阈值（对应 policy.json 里的 `thresholdDeg`） |
| **导出 JSON** | 下载事件日志，可给实验分析用 |

## 现在实现了什么

```
摄像头/演示帧 → 320×240 降采样 → 灰度
   ├─ 地平线倾斜：逐列找最强水平边 → 加权最小二乘拟合 → 角度 + 置信度
   ├─ 明暗：平均亮度 / 暗部占比 / 高光溢出
   └─ 反光：高亮 + 低饱和像素占比
        ↓
   规则层：阈值 + 置信度 + 冷却(3s) + 全局间隔(8s) + 开关 + 优先级
        ↓
   呈现层：一句话横幅 + 参考线 + 旋转箭头；事件写入日志
```

三条件开关（对应设计里的评估设计）目前是"阈值滑杆 + 开关"，后续可直接改成 A/B/C 三种模式。

### 关于"摄像头没法转"

笔记本/台式摄像头固定在桌上，物理上无法倾斜。两种办法：

1. **虚拟倾斜**（已实现）：把视频旋转后再送进检测，等价于相机歪了 N°。参考线会跟随旋转角度，提示逻辑完全一样；
2. **用手机**：手机浏览器打开同一个页面，物理倾斜手机即可，代码无需改动（场景本身被旋转，检测照样读到倾斜的地平线）。

注意：虚拟倾斜验证的是"检测→规则→提示"这条链路，不验证真实光学的倾斜（那部分在手机上测）。

## 手机上试

摄像头 API 需要安全上下文：

- 桌面：`http://127.0.0.1` 就算安全上下文，可直接用；
- 手机（同一 Wi-Fi）：临时开个 HTTPS 隧道，例如
  `cloudflared tunnel --url http://127.0.0.1:8765`
  用隧道给的 https 地址在手机浏览器打开；
- 或者在电脑 Chrome 里用 `chrome://inspect` 做端口转发（Android）。
