# AI 拍照助手 · AIPhotoCamera

> 一个会"看着"你取景的相机 App —— 它认得画面里的主体，告诉你手机该往哪转，构图对了再按快门。

HKUST-GZ **AIAA4435 Interactive AI Systems** 课程项目。

---

## 这个项目在解决什么问题

普通手机相机**不告诉你**三件事：

1. **手机是不是端平了** —— 拍出来的地平线歪了，往往事后才发现
2. **主体该放在哪** —— 三分法大家都知道，但没人在取景时告诉你该往哪挪
3. **这次拍得好不好** —— 拍完才知道，只能重拍

用户调研（n=28）里，**71% 的人单次拍摄 ≤20 秒**，**64% 经常重拍**，**43% 干脆放弃**。
问题不在于不会构图，而在于**取景时没有即时反馈**。

这个 App 的做法：**在取景阶段就把该做的事告诉用户**。

## 核心设计

### 三个元素，各司其职

| 元素 | 是什么 | 用户要做什么 |
|---|---|---|
| **主体框** | 锁定中的那个物体（只画这一个） | 点屏幕可换 |
| **实点**（黄靶心） | **镜头中心应该到达的位置**，由构图建议算出 | — |
| **虚点**（白十字） | **镜头中心**，固定在屏幕正中 | 把它挪到实点上去 |

**用户唯一的动作**：移动手机，让白十字压到黄靶心，按快门。

### 分层架构

```
┌─────────────────────────────────────────────────┐
│  前台（用户看得到的）                              │
│  ├ 主体框        锁定谁                           │
│  ├ 实点 / 虚点   往哪挪 + 现在在哪                 │
│  └ 一句话提示    "手机往右" / "构图可以，直接拍"    │
├─────────────────────────────────────────────────┤
│  后台（用户看不到的）                              │
│  ├ 主体检测      ML Kit 单目标实时流 + 点击独立检测 │
│  ├ 构图建议      三分法 + 留白规则 → 算出实点       │
│  ├ 实点稳定      滞后带，消除抖动                   │
│  └ 水平仪        重力传感器 + 镜头偏差校准           │
└─────────────────────────────────────────────────┘
```

## 关键设计决策（以及踩过的坑）

这部分是项目的技术核心，每个决策都有明确的理由。

### 1. 为什么放弃了"检测画面里的线"

最初的方案是检测画面里的水平/竖直边，然后画在屏幕上。**失败了两次**：

- **第一次**：画两条固定基准线让用户对齐 —— 但固定线只说明"屏幕中心在哪"，不说明"手机歪了多少"，用户根本没法读出偏移量。
- **第二次**：把算法实际检测到的线画出来 —— 用户能看见算法在看哪条边了，**但看见也没用**，因为算法选边的依据（对比度最高）跟"主体在哪"没有关系，他没能力改变它。

**结论**：问题在最上游。先定主体，才谈得上构图。

### 2. 为什么水平仪必须用重力传感器

相机模组有 **1~3° 的装配偏差**。画面里"看起来正"的水平线，跟手机框真正水平，本来是两回事。

所以判"正不正"必须用**重力传感器**（不依赖画面内容，白墙天空也能用），再通过一次校准把**镜头装配偏差**和**传感器基准误差**分别存下来。

> 诚实说明：这套水平仪**只对竖持有效**。拍平面时重力几乎落在 z 轴，roll 在数学上退化。

### 3. ML Kit 的正确用法（文档纠正了一个重要误解）

[官方文档](https://developers.google.cn/ml-kit/vision/object-detection/android?hl=zh-cn) 写得很明确：

> `STREAM_MODE`：低延迟，但最初几次调用可能返回不完整结果；会分配跟踪 ID。
>
> 该 API 针对两个核心场景优化：
> 1. **实时检测并跟踪取景器中最突出的对象**
> 2. **检测静态图片中的多个对象**

也就是说：**实时场景官方做法是单目标**，多目标是静态图片的做法。
早期版本两个都开 `enableMultipleObjects()`，导致每帧在最多 5 个对象间重新分配 trackingId —— 框乱跳、锁不住、别的物体还干扰。

现在拆成两个实例：

| 实例 | 模式 | 用途 |
|---|---|---|
| `streamDetector` | `STREAM_MODE` + 单目标 | 实时跟踪，~10fps |
| `pickDetector` | `SINGLE_IMAGE_MODE` + 多目标 | 点击时跑一次，确定"点的是哪个" |

### 4. 实点为什么需要滞后带稳定器

实点公式是 `实点 = 0.5 + (主体位置 - 目标位置)`，**框抖 1%，实点就抖 1%**。

低通滤波会让跟手变迟钝，所以改用**滞后带（hysteresis）**：

| 情况 | 行为 |
|---|---|
| 主体偏移 **< 4.5%** | 实点**纹丝不动** |
| 主体偏移 **> 4.5%** | 连续 **2 帧**同向确认才更新 |
| 更新之后 | 主体重新获得整个带宽余量 |

依据是**三分法本身就是宽容的**：主体不必精确落在 1/3 处，落在附近一片区域都是好构图。

实测效果（单测）：40 帧抖动输入下，无稳定器实点持续位移，有稳定器**完全不动**。

## 快速开始

### 安装 APK

| 文件 | 说明 |
|---|---|
| `releases/AI-Photo-camera-P2-v9.apk` | 最新版（27.5 MB） |
| `releases/AI-Photo-camera-P1-v3.apk` | 基础相机存档（6.3 MB） |

APK 未上架商店，需要允许"安装未知来源应用"。**仅支持 ARM 设备**（`arm64-v8a` / `armeabi-v7a`），不含 x86 模拟器支持。

### 构建

环境：JDK 17 + Android SDK 34。

```bash
cd android

# 需要先创建 local.properties 指向你的 SDK
echo "sdk.dir=/path/to/android-sdk" > local.properties

./gradlew assembleDebug        # 产物：app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest    # 跑 48 项单测
```

### 使用

1. 启动后先点 **「校准水平」**，按靶心提示校准一次（只需一次，会保存）
2. 点屏幕锁定想拍的主体，或点 **「自动锁定」**
3. 移动手机，让白十字压到黄靶心
4. 按快门

> 长按左上角 HUD 可打开**日志查看器**（支持过滤、复制、分享），调试时很有用。

## 已知限制

| 限制 | 说明 |
|---|---|
| **水平仪只对竖持有效** | 拍平面时重力落在 z 轴，roll 数学上退化 |
| **ML Kit 是粗分类模型** | 远景小主体、低对比度主体识别率不高 |
| **留白规则未生效** | ML Kit 不提供人物朝向，目前只走三分法 |
| **APK 27.5 MB** | ML Kit bundled 模型的体积代价（换来离线可用） |
| **仅 ARM** | 为控制体积去掉了 x86 |
